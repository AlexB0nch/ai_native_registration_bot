# Обработчик форм `/api/register`

Техническое задание от 08.10.2026. Обработчик живёт **в этом репозитории**
(решение владельца). Логику бота `@AI_native_reg_bot` делают отдельно,
бриф для той сессии лежит в [BOT-BRIEF.md](BOT-BRIEF.md). Ниже описан и
договор между ними, его нельзя менять с одной стороны.

## Зачем отдельный сервис

Сайт — статика, которую раздаёт nginx, и выполнять код он не умеет.
Принять форму, сохранить заявку и написать владельцу должен маленький
сервис рядом с сайтом. На саму страницу он не влияет: правило «ноль JS
на странице» не нарушается, формы остаются обычным HTML.

```
браузер ── POST /api/register ──→ сервис форм ──┬─ дописывает заявку в файл на томе
                                                ├─ пишет владельцу через @AI_native_reg_bot
                                                ├─ (когда бот готов) отправляет заявку в бот
                                                └─ 303 → страница «Спасибо» или «Ошибка»
```

## Где лежит и как запускается

| Что | Где |
|---|---|
| Код | `forms/server.mjs`: один файл на чистом Node 22 (`node:http`), **без зависимостей** |
| Сборка | `forms/Dockerfile` (`node:22-slim`), отдельно от `Dockerfile` сайта |
| Деплой | второй ресурс Coolify из того же репозитория, base directory `forms/` |
| Данные | том Coolify `/data`, файл `/data/registrations.jsonl`: одна заявка на строку |
| Маршрут | `alexshein.com/api/*` → сервис форм (варианты ниже) |

Как отправить `/api/` на сервис, по порядку предпочтения:
1. **Домен с путём в Coolify.** Ресурсу форм ставится домен
   `https://alexshein.com/api`, и прокси Coolify сам отправляет этот путь
   на сервис. `nginx.conf` сайта не меняется. Перед выбором проверить
   на текущей версии Coolify, что маршрутизация по пути работает.
2. **Правило в `nginx.conf` сайта:** `location /api/ { proxy_pass http://<имя контейнера форм>:3000; }`.
   Оба ресурса нужно подключить к общей сети Coolify.

В обоих вариантах запрос остаётся на `alexshein.com`, поэтому браузер
передаёт полный адрес страницы вместе с UTM. Ещё один момент: DDoS-Guard
перед сайтом кэширует ответы, путь `/api/` нужно исключить из кэша.

### Переменные окружения

| Имя | Что |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен `@AI_native_reg_bot`, нужен для уведомлений владельцу |
| `OWNER_CHAT_ID` | чат владельца, куда приходят заявки |
| `ALLOWED_ORIGIN` | `https://alexshein.com` |
| `BOT_WEBHOOK_URL` | адрес бота для приёма заявок с сайта; пока пусто — шаг пропускается |
| `BOT_WEBHOOK_SECRET` | общий секрет с ботом, уходит в заголовке `X-Webhook-Secret` |
| `DATA_DIR` | `/data` |

Секреты хранятся только в Coolify и никогда не попадают в репозиторий.

## Что принимает

`POST /api/register`, тело `application/x-www-form-urlencoded`. Поля описаны
в [LANDING-COPY.md](LANDING-COPY.md), раздел 5.

| Поле | Практикум | Курс | Проверка |
|---|---|---|---|
| `form` | `practicum` | `course` | только эти два значения |
| `name` | да | да | 1–100 символов |
| `contact` | да | да | `@username`, `t.me/username` или email, до 100 символов |
| `role` | да | да | одно из четырёх значений формы |
| `tariff` | — | да | `early` / `standard` / `pro`; `early` принимается только до 2 ноября включительно по Москве |
| `task` | — | нет | до 1000 символов |
| `invoice` | — | нет | галочка |
| `consent` | да | да | должна быть отмечена |
| `website` | ловушка | ловушка | непустое значение означает бота, такую заявку молча пропускаем |

## Что делает

1. Проверяет `Origin` (должен совпадать с `ALLOWED_ORIGIN`) и ограничивает
   частоту: не больше 5 заявок с одного адреса за 10 минут (адрес берётся
   из `X-Forwarded-For`, который ставит прокси).
2. Проверяет поля по таблице выше.
3. Из `Referer` достаёт `utm_source`, `utm_medium`, `utm_campaign`,
   `utm_content` и адрес страницы.
4. Нормализует контакт: `@Name`, `t.me/Name` и `Name` превращаются в
   `telegram_username = name` (в нижнем регистре); email сохраняется отдельно.
5. Дописывает заявку строкой JSON в `registrations.jsonl` (формат ниже).
6. Пишет владельцу в Telegram: тип, имя, контакт, роль, тариф, задача, UTM.
   Если указана только почта, добавляет пометку «без Telegram, напомнить на почту».
7. Если задан `BOT_WEBHOOK_URL`, отправляет туда ту же заявку JSON-ом.
   Ошибка на этом шаге не мешает человеку: заявка уже сохранена, а владелец
   получает отдельное предупреждение.
8. Отвечает `303 See Other`:
   - практикум → `/ai-native/spasibo-praktikum`;
   - курс → `/ai-native/spasibo-kurs`;
   - ошибка проверки или записи → `/ai-native/oshibka`.

`GET /api/health` → `200 ok` для проверки здоровья в Coolify.

## Формат заявки

Одинаковый в файле и в запросе к боту. Это и есть договор с ботом.

```json
{
  "id": "01JABCD…",
  "created_at": "2026-10-20T12:34:56+03:00",
  "source": "site",
  "form": "practicum",
  "name": "Ирина",
  "contact_raw": "@irina_ops",
  "telegram_username": "irina_ops",
  "email": null,
  "role": "opex",
  "tariff": null,
  "task": null,
  "invoice": false,
  "page": "https://alexshein.com/ai-native?utm_source=tgads&utm_content=opex",
  "utm": { "source": "tgads", "medium": null, "campaign": null, "content": "opex" }
}
```

`role`: `consultant` / `opex` / `transformation` / `other`.
`tariff`: `early` / `standard` / `pro` / `null`.

## Связь формы с Telegram

Бот не может написать человеку первым. Поэтому:
- на странице «Спасибо» главная кнопка ведёт в бота
  (`?start=prk_web` или `?start=crs_web`);
- когда человек нажимает «Запустить», бот ищет его заявку с сайта по
  `telegram_username` и привязывает к ней чат. Если не нашёл, задаёт
  вопросы сам, как при записи прямо из бота;
- тем, кто оставил только почту, владелец пишет сам; в уведомлении есть
  пометка.

## Что не входит

- Оплата. Ссылку ЮKassa выдаёт бот после подтверждения
  ([BOT-BRIEF.md](BOT-BRIEF.md)).
- Письма на почту. Если понадобятся, это отдельный шаг.
- Политика персональных данных. Её пишет владелец, формы ссылаются на `/privacy`.

## Готово, когда

- [ ] обе формы со страницы доходят: строка в файле и сообщение владельцу;
- [ ] заполненная ловушка, неотмеченная галочка и чужой `Origin` не создают заявок;
- [ ] `early` после 2 ноября отклоняется;
- [ ] UTM со страницы попадают в заявку;
- [ ] перезапуск контейнера не теряет заявки: файл лежит на томе;
- [ ] в репозитории нет ни одного секрета;
- [ ] сборка сайта и все четыре проверки из `AGENTS.md` проходят как раньше.
