# CLAUDE.md — правила для AI-ассистентов в `ai_native_registration_bot`

Процесс взят из [AlexB0nch/pppp](https://github.com/AlexB0nch/pppp) и упрощён
под один сервис. Нарушение правил — повод откатить изменения.

## Роли

| Роль | Кто | Что делает |
|---|---|---|
| **Owner** | Александр Шеин | Ставит цели, отвечает на вопросы, даёт явное «ок, мёрджи». Сам PR не мёрджит. |
| **Orchestrator** | Claude Code | Пишет SPEC и карточки задач, запускает Implementer'а, ревьюит PR по чеклисту, мёрджит **только** после явного «ок, мёрджи» Owner'а. |
| **Implementer** | Claude Code в отдельном worktree (субагент) | Читает SPEC, пишет код и тесты в ветке из SPEC, открывает PR. |

## Точка правды

- Код: ветка `main`. Прод (Coolify, `https://reg.alexshein.com`) — зеркало `main`.
- Факты о курсе (даты, время, цены, ссылки): **только** `config/facts.yaml`.
- Тексты бота: `config/texts.yaml`. В коде и в промпте модели цены и даты не пишутся.
- База знаний для ответов: `knowledge/*.md`, собирается `scripts/build_knowledge.py`
  из `materials/`, после сборки её можно править руками.
- Решения владельца по курсу: `materials/COURSE-DECISIONS.md` (копия из `alexshein.com`).

## Workflow

```
SPEC (docs/SPEC-*.md) → ветка → код + тесты → PR → ревью Orchestrator → «ок, мёрджи» от Owner → merge → Coolify redeploy
```

Подробно: [docs/WORKFLOW.md](docs/WORKFLOW.md). Задачи: [tasks/INDEX.md](tasks/INDEX.md).
План и сроки: [docs/PLAN.md](docs/PLAN.md). Устройство: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Orchestrator

1. Каждая задача начинается с `docs/SPEC-<TASK-ID>.md` и `tasks/<TASK-ID>.md`, `tasks/INDEX.md` обновляется.
2. Сам правит только `docs/`, `tasks/`, `materials/`, `.github/` (кроме workflow), `CLAUDE.md`, `README.md`.
   Код (`app/`, `alembic/`, `scripts/`, `tests/`, `config/`, `knowledge/`, Docker, CI) — через Implementer'а.
3. Ревьюит PR по чеклисту из [docs/WORKFLOW.md](docs/WORKFLOW.md#чеклист-ревью).
4. **Никогда не мёрджит без явного «ок, мёрджи» Owner'а.** Одобрение одного PR не распространяется на другие.

## Implementer

1. Читает SPEC целиком, работает в ветке из `Branch:`, трогает только файлы из `Files:`.
2. Пишет тесты из `Tests:`; перед PR: `ruff check .` и `pytest -q` зелёные.
3. PR: заголовок `<TASK-ID>: <описание>`, тело по `.github/pull_request_template.md`.

## Железные правила кода

- Секреты только в переменных окружения. `.env` не коммитится, `.env.example` — да.
- Персональные данные (имя, почта, телефон, username, текст вопросов) **не пишутся в логи**.
  В логах — только внутренние id.
- Время храним в UTC (`timestamptz`), показываем в Europe/Moscow с пометкой «МСК».
- Бот работает **одним процессом** (`uvicorn --workers 1`, одна реплика): в нём планировщик рассылок.
- Тон текстов: на «вы», спокойно и конкретно, не больше одного эмодзи. Нельзя:
  «уникальный», «успейте», «прорыв», «революционный», таймеры и фиктивный дефицит,
  обещания «стать разработчиком», «заменить аналитика», «стратегия из одного запроса»,
  «production без IT», проценты экономии. Страны и города не упоминать (МСК — можно).
- Название бесплатной встречи — только «практикум» (не «разбор», не «вебинар»).

## Нельзя

- Коммитить секреты, force-push в `main`, мёрджить без Owner'а, править прод руками
  (в Coolify меняются только переменные окружения), игнорировать красный CI.
